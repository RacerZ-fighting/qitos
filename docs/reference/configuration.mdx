QitOS is configured through three overlapping layers:

1. **`AgentModule.run()` keyword arguments** — the normal per-run entrypoint
2. **`Engine` constructor keyword arguments** — lower-level runtime control
3. **Environment variables** — provider credentials and model defaults

---

## YAML validation

`load_agent_config(path)` parses YAML with `yaml.safe_load()`, resolves explicit
`${ENV_VAR}` placeholders, and validates the complete document through private
Pydantic input models. Unknown fields, wrong nested types, empty Tool paths, and
non-positive step, token, or context-window limits raise a standard
`pydantic.ValidationError` with structured field locations. QitOS then converts the
validated input into the public `AgentConfig`, `ModelConfig`, and `DatasetItem`
dataclasses; Pydantic models do not become runtime state.

Configuration is strict about YAML scalar types. Write `max_steps: 10`, not
`max_steps: "10"`. Arbitrary application values remain allowed inside the explicit
`environment` and `metadata` mappings.

## OpenAI transport mode

`OpenAIModel`, `OpenAICompatibleModel`, and their async variants support two
explicit transport modes:

| `api_mode` | Behavior |
|---|---|
| `chat_completions` | Default. Uses `/v1/chat/completions` and preserves existing QitOS behavior |
| `responses` | Opt-in. Uses `/v1/responses`, preserves ordered native output items, and correlates function calls and outputs with `call_id` |

Configure the mode in YAML:

```yaml
model:
  provider: openai
  model: gpt-5
  api_mode: responses
```

Or construct a model directly:

```python
from qitos.models import OpenAIModel

llm = OpenAIModel(
    model="gpt-5",
    api_mode="responses",
)
```

Responses mode supports synchronous, asynchronous, and typed streaming calls.
QitOS replays the provider's ordered output items and
`function_call_output` items during a tool loop, so no mutable
`previous_response_id` state is required. Active native tool rounds remain
atomic during history compaction.

The typed stream preserves request lifecycle, item, content, refusal, reasoning,
function-argument, and terminal events. Text or reasoning present only in completed
output is emitted once at the terminal boundary. Interleaved function arguments are
tracked by item identity. An `incomplete` response retains its native evidence and
finish reason but never exposes a function call for execution; malformed or
contradictory terminal lifecycle events raise `ModelTransportError`.

<Warning>
OpenAI-compatible providers may implement only part of `/v1/responses`.
QitOS never silently falls back to Chat Completions after a Responses request
fails. Select `chat_completions` explicitly for endpoints that do not support
Responses.
</Warning>

`CompactHistory.retrieve()` remains a synchronous history contract. When its configured
`llm` is an async-native QitOS `Model`, compaction uses the bounded heuristic summary
instead of calling that model or creating an event-loop bridge. Summary metadata and
context events record `summarizer_mode="heuristic_async_model"`. Applications may still
provide an explicit synchronous summary callable; its errors remain visible and use the
existing bounded failure circuit.

Reasoning items are treated as opaque continuation state. Trace summaries keep
safe item descriptors and provider-authorized summaries, but omit encrypted
reasoning continuation payloads.

### Reasoning effort and continuation

`build_model_for_preset(...)` accepts one provider-neutral `reasoning_effort` value:
`low`, `medium`, `high`, `xhigh`, or `max`. QitOS resolves it once against the
selected model-family policy and shares the resulting request defaults across sync,
async, and streaming calls. Unsupported values map to the nearest advertised level;
for example, GPT-5.6 preserves `max`, while the older OpenAI policy caps it at
`xhigh`.

The Anthropic family preset builds the native Messages adapter. Claude 4.5 models map
the same effort levels to manual thinking budgets from 1,024 to 16,384 tokens, clamped
to preserve at least 1,024 tokens and one quarter of `max_tokens` for the visible
answer. Per-call `thinking` options can override the model defaults. When thinking is
enabled, QitOS omits `temperature` so the provider uses its compatible
sampling behavior. Harness metadata reports the clamped value as
`reasoning.effective_budget_tokens`. The preset delivers the current turn's tool
schemas through the native Messages API and prefers typed `tool_use` calls over text
parsing; stale `default_request_kwargs.tools` cannot replace that turn projection.

For official OpenAI Responses requests, QitOS asks for
`reasoning.encrypted_content`, preserves fields delivered by output-item events, and
replays the ordered native items on the next tool round. It does not add that
OpenAI-only `include` value to compatible providers such as Kimi. Compatible Chat
`reasoning_content` remains continuation metadata and is never substituted for an
empty visible answer.

### Model retry and Engine deadlines

`OpenAIModel`, `OpenAICompatibleModel`, and their async variants share the same
transport implementation and accept the following controls:

| Argument | Default | Behavior |
|---|---:|---|
| `timeout` | `120` | Non-stream request timeout |
| `max_attempts` | `2` | Total attempts including the first request |
| `stream_idle_timeout` | `60` | Maximum seconds without progress on a model stream |
| `retry_window_seconds` | `300` | Total recovery window after the first retryable failure |

Model streams activate this policy. QitOS creates the corresponding OpenAI-compatible
async SDK client with `max_retries=0`, while `ModelRetryPolicy` remains the only
retry owner. It retries recognized connection failures, timeouts, 408, 409, 429, and
5xx responses and honors bounded
`Retry-After`, `retry-after-ms`, and `x-should-retry` hints. Local validation errors
and ordinary 4xx responses fail immediately.

When an Engine run has a relative or absolute runtime limit, it binds one logical
model-request deadline. Every attempt recalculates its provider timeout from live
remaining time, retry backoff observes both deadline and cancellation, and no new
attempt starts after either becomes terminal. Provider cancellation propagates through
the async stream instead of detaching work onto a daemon thread.

The Engine publishes non-terminal text, reasoning, and tool-call deltas immediately.
Connection failures and stream failures before the first provider event may retry within
both the `max_attempts` budget and `retry_window_seconds`, measured from the first
retryable failure. Once an event has arrived, QitOS never replays that attempt: a later
failure closes the stream and surfaces the error, so visible output and tool-call deltas
cannot be duplicated. The terminal event is held until provider EOF confirms that no
late event follows it. A healthy long response may run beyond `timeout` while events
continue only when no earlier Engine deadline applies; `stream_idle_timeout` detects a
stalled response. Direct callers use the same live `stream()` contract.

All model stream paths use discriminated `ModelStreamEvent` values. Text, reasoning,
ToolCall deltas, native items, usage, lifecycle, completion, and failure each have an
explicit kind. A `COMPLETED` event retains the provider's actual `finish_reason` and
final model fields. Chat
tool-argument fragments use `event_type="tool_call.delta"`, while Responses keeps its
provider event type and sequence metadata. A provider stream that closes without its
terminal event raises `ModelTransportError` instead of inventing a successful finish.
Existing Engine stream handlers keep `on_start/on_delta/on_end`; richer handlers may
optionally implement `on_chunk(event)` and `on_error(exc)` without changing the required
protocol.

Native calls are complete-before-execute. Chat exposes calls only for a tool-call finish
reason. Anthropic additionally requires a closed `tool_use` block whose accumulated JSON
is an object and whose message stops with `tool_use`. Output-limit, unclosed, malformed,
or contradictory calls are listed in terminal `invalid_tool_calls` metadata and are not
published as executable calls or replayed as native items.

```python
from qitos.models import OpenAICompatibleModel

llm = OpenAICompatibleModel(
    model="compatible-model",
    base_url="https://provider.example/v1",
    api_mode="responses",
    timeout=120,
    max_attempts=2,
    stream_idle_timeout=60,
    retry_window_seconds=300,
)
```

## AgentModule.run() arguments

All of the following can be passed to `agent.run(task, ...)`. This is the canonical user-facing configuration surface for QitOS runs.

<AccordionGroup>

<Accordion title="Task and execution">

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `task` | `str \| Task` | required | Task objective string or structured `Task` object |
| `max_steps` | `int \| None` | `None` | Override `TaskBudget.max_steps`; also sets `state.max_steps` via `state_kwargs` |
| `return_state` | `bool` | `False` | Return the full `EngineResult` instead of just `state.final_result` |
| `workspace` | `str \| None` | `None` | Path to workspace root; automatically constructs a `HostEnv` and sets `env_spec` on the task |
| `env` | `Any` | `None` | Explicit `Env` instance; takes precedence over `workspace` |

</Accordion>

<Accordion title="Parsing and decisions">

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `parser` | `Any` | `None` | Parser (a component that converts raw model output into a typed Decision) instance (e.g. `ReActTextParser`, `JsonDecisionParser`) forwarded to the `Engine` |
| `search` | `Any` | `None` | `Search` strategy instance for `branch` decisions (e.g. `DynamicTreeSearch`) |
| `critics` | `List[Any] \| None` | `None` | List of `Critic` (a module that evaluates each step and can trigger retries or stops) instances evaluated after each step |
| `stop_criteria` | `List[Any] \| None` | `None` | Custom stop criteria list; replaces the default `FinalResultCriteria` |
| `history_policy` | `Any` | `None` | `HistoryPolicy` instance controlling message history window |

</Accordion>

<Accordion title="Tracing and rendering">

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `trace` | `Any` | `None` | `True` to enable default `TraceWriter`; pass a `TraceWriter` instance for full control; `False`/`None` disables tracing only if `trace_writer` is not already set in `engine_kwargs` |
| `trace_logdir` | `str` | `"./runs"` | Directory where trace run subdirectories are created |
| `trace_prefix` | `str \| None` | `None` | Prefix for the auto-generated run ID; defaults to `agent.name` |
| `render` | `Any` | `None` | `True` to enable the default `ClaudeStyleHook` render hook; pass a hook instance for custom rendering |
| `theme` | `str` | `"research"` | Theme name passed to the render hook |

</Accordion>

<Accordion title="Hooks and engine passthrough">

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `hooks` | `List[Any] \| None` | `None` | Additional `EngineHook` instances appended to the Engine's hook list |
| `render_hooks` | `List[Any] \| None` | `None` | Additional render hook instances merged into `hooks` |
| `engine_kwargs` | `Dict[str, Any] \| None` | `None` | Any `Engine` constructor keyword argument; lower-priority than the explicit arguments above |
| `**state_kwargs` | `Any` | | Extra keyword arguments forwarded to `agent.init_state()` |

</Accordion>

</AccordionGroup>

**Minimal example**

```python
result = agent.run(
    task="Analyse the repository and list all public API functions.",
    workspace="/path/to/repo",
    max_steps=20,
    trace_logdir="./experiment-runs",
    trace_prefix="api-analysis",
)
```

## Engine constructor arguments

When you construct an `Engine` directly (or via `engine_kwargs`), these parameters are available:

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `agent` | `AgentModule` | required | The agent whose hooks the Engine calls |
| `budget` | `RuntimeBudget \| None` | `RuntimeBudget(max_steps=10)` | Local step, time, token, cost, Tool, and Child limits |
| `budget_ledger` | `BudgetLedger \| None` | new Root ledger | Shared token/cost owner passed unchanged to Child Engines |
| `validation_gate` | `StateValidationGate \| None` | default gate | Validates state before and after each phase |
| `recovery_handler` | `RecoveryHandler \| None` | `None` | Callable `(state, phase, exc) -> None` invoked on recoverable errors |
| `recovery_policy` | `RecoveryPolicy \| None` | `RecoveryPolicy()` | Controls retry behaviour and backoff |
| `trace_writer` | `TraceWriter \| None` | `None` | Writes trace (a structured log of all run events and steps) artifacts; set via `AgentModule.run(trace=True)` |
| `parser` | `Parser[ActionT] \| None` | `None` | Parser (a component that converts raw model output into a typed Decision); converts raw LLM output to `Decision` |
| `stop_criteria` | `List[StopCriteria] \| None` | `[FinalResultCriteria()]` | Ordered stop criteria evaluated after each step |
| `branch_selector` | `BranchSelector \| None` | `FirstCandidateSelector()` | Selects among `branch` candidates |
| `search` | `Search \| None` | `None` | Search strategy for expanding and scoring branch candidates |
| `critics` | `List[Critic] \| None` | `[]` | Critics (modules that evaluate each step and can trigger retries or stops) evaluated after each step |
| `env` | `Env \| None` | `None` | Environment for observe/step/is_terminal lifecycle |
| `history_policy` | `HistoryPolicy \| None` | `HistoryPolicy()` | Controls how history messages are assembled for model calls |
| `hooks` | `List[EngineHook] \| None` | `[]` | Engine lifecycle hooks |
| `render_hooks` | `List[Any] \| None` | `None` | Render hooks merged into `hooks` |

**`RuntimeBudget` fields**

```python
@dataclass
class RuntimeBudget:
    max_steps: int = 10
    max_runtime_seconds: Optional[float] = None
    max_tokens: Optional[int] = None
    max_cost_usd: Optional[float] = None
    max_tool_concurrency: int = 4
    max_children: int = 4
    deadline_monotonic: Optional[float] = None
```

`max_runtime_seconds` starts when the Engine run is admitted. `deadline_monotonic` is an
absolute `time.monotonic()` deadline supplied by an outer scheduler, so time spent before
Engine admission is not accidentally restored. When both are set, the earlier deadline
wins. A `Task` object's relative budget values override the Engine defaults for that run;
the outer absolute deadline is retained.

## Environment variables

| Variable | Required | Description |
|----------|----------|-------------|
| `OPENAI_API_KEY` | Yes (for OpenAI / compatible APIs) | API key sent in the `Authorization` header. Used by `OpenAIModel` and `OpenAICompatibleModel` |
| `OPENAI_BASE_URL` | Yes (for compatible APIs) | Base URL of the API endpoint. Required by `OpenAICompatibleModel`; optional for `OpenAIModel` (defaults to `https://api.openai.com/v1`) |
| `QITOS_API_KEY` | No | Compatibility API key read by `ModelConfig.from_env()` when `OPENAI_API_KEY` is not set |
| `QITOS_MODEL` | No | Default model identifier read by `ModelConfig.from_env()` |
| `AZURE_OPENAI_API_KEY` | Only for Azure | API key for Azure OpenAI. Used by `AzureOpenAIModel` |
| `AZURE_OPENAI_ENDPOINT` | Only for Azure | Endpoint URL for Azure OpenAI |
| `AZURE_OPENAI_DEPLOYMENT` | No | Deployment name for Azure OpenAI |
| `AZURE_OPENAI_API_VERSION` | No | API version; defaults to `2024-02-15-preview` |

**Example `.env` file**

```bash
# OpenAI-compatible endpoint (e.g. SiliconFlow, Ollama proxy)
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=https://api.siliconflow.cn/v1/
```

## Trace output directory structure

By default, `AgentModule.run()` writes traces to `./runs/`. Each run creates one subdirectory:

```
<trace_logdir>/
└── <trace_prefix>_<YYYYMMDD_HHMMSS_ffffff>/
    ├── manifest.json    # Run metadata and final summary
    ├── events.jsonl     # All runtime events (one JSON object per line)
    └── steps.jsonl      # All step records (one JSON object per line)
```

**Auto-generated run ID format**

```
<agent.name>_<YYYYMMDD_HHMMSS_ffffff>
```

Override the prefix with `trace_prefix`:

```python
agent.run(task="...", trace_prefix="experiment-01")
# → runs/experiment-01_20260407_120000_123456/
```

**Pointing `qita board` at your trace directory**

```bash
qita board --logdir ./runs
```

<Note>
Tracing is enabled by default in `AgentModule.run()`. Set `trace=False` only for quick interactive experiments — disabling tracing means runs cannot be replayed or inspected with `qita`.
</Note>
