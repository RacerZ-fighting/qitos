---

QitOS 在一条最小异步 agent loop 上构建可复现的 LLM 智能体（agent）：`Message ->
Model -> ToolCall -> ToolResult`，由 `Agent` façade 驱动。无论你是在原型化新的
智能体策略，还是交付面向真实工作流的编程智能体，运行结果始终可追踪、可组合、可复现。

一个长时间运行的 QitOS 编程任务不应该退化成难以理解的胶水代码。

![QitOS 实时编程运行](/images/demo.gif)

## QitOS 中的两种编写方式

QitOS 提供两种智能体编写方式。

### façade 优先

这是默认入口：直接组合运行时。

你选择：

- 模型（任意兼容 OpenAI、Anthropic 或本地适配器）
- 系统提示词（prompt）
- 工具面（类型化工具的 `ToolRegistry`）
- 轮次与时间预算

```python
agent = Agent(model=model, tool_registry=registry, system_prompt="...", max_turns=10)
result = await agent.prompt("检查这个项目")
```

一切都是显式的：没有隐藏规划器，没有第二个编排器。

### 预设优先（preset-first）

当你需要稳定基线（baseline）或快速切换模型家族时，可以选择预设优先方式。

你会从这些层开始：

- 家族预设（family preset）
- 适配层策略（harness policy）
- 预设工具构建器

这条路径尤其适合同一个智能体在 Qwen、Kimi、MiniMax、`gpt-oss` 与 Gemma 4 之间切换的场景。

## QitOS 适合谁

- **研究者**：在最小、可检查的 loop 上原型化新的智能体方法，并获得可回放（replay）、可对比、可发表的追踪记录（trace）。
- **智能体构建者**：在稳定执行循环上构建使用工具的智能体，而不是反复手写围绕裸 LLM 调用的框架胶水。
- **评测者**：用 qita 把结构化运行产物变成可比较、可审查的证据。

## 核心能力

### 可复现的运行

每次 QitOS 运行都可以持久化一份 append-only JSONL journal：模型事务、Tool
started/terminal 记录、已提交 turn，以及恰好一个运行终态记录。journal 是回放、
恢复与 fork 的 canonical 真源。

### 内置可观测性：qita

`qita` 是 QitOS 自带的追踪记录查看器。任意一次运行结束后，启动看板即可查看逐步执行、回放运行轨迹，并导出（export）成独立 HTML。

```bash
qita board --logdir runs
```

看板默认运行在 `http://127.0.0.1:8765`，当新运行出现时会自动刷新。

### 严格准入的类型化工具

工具声明严格的输入 schema，并经同一条准入/执行管线运行：校验、权限、有界并发、
超时，以及每个调用恰好一个终态 `ToolResult`——包括被拒绝、超时和被取消的调用。
并行批次按输入顺序提交结果。

### 子智能体

子智能体与父级使用同一个 `Agent` 实现，只是工具与预算被收窄。Run 级 supervisor
提供持久 handle、后台执行、父级消息、等待、中断和基于 journal 的恢复。

### MCP 集成

把 Model Context Protocol（MCP）服务器桥接进 QitOS 工具注册表。支持 stdio 或 HTTP
传输、工具过滤与异步服务器生命周期管理。

## 特色设计

这些设计决定了 QitOS 不只是智能体工具集合，而是一套清晰的运行时（runtime）方法论。

### 单 loop 架构

QitOS 最核心的约束只有一条：一次运行只有一条 agent loop。

- `Agent` façade 持有 transcript、生命周期事件与 steering 队列
- loop 负责 turn 机制：每个 turn 一份不可变的模型/工具快照
- 工具、记忆、journal 与追踪都附着在这条主链路上，而不是另起编排器

### 以预设为优先的模型切换

QitOS 提供可复用的编写模块，不需要每个智能体从零开始组装一切：

- `coding_tools(...)`、`advanced_coding_tools(...)`、`web_tools()`、`task_tools(...)`
- `WindowMemory`、`SummaryMemory`、`VectorMemory`、`MarkdownFileMemory`
- 家族预设与适配层策略用于切换 provider

研究者可以调整策略，而不必重搭整套基础设施。

### 追踪优先的可观测性

QitOS 的假设是：只要一次运行重要，它就应该可检查。

每次追踪运行都会产出结构化产物（artifact），而 `qita` 会把它们变成：

- 用于比较多次实验的看板
- 用于逐步理解单次运行的回放
- 用于分享与审计的导出

### 不引入新运行时的领域专门化

领域智能体仍然是普通的 QitOS 智能体。领域行为体现在：

- 提示词策略
- 工具组合
- 子智能体分解

专门化因此更容易理解，也更容易复现。

## 当前状态

<Warning>
QitOS 当前处于 **Beta** 阶段。运行时迁移期间继续保持 trace/qita 与 canonical durable records 的行为。用于生产环境时请固定版本并关注 Changelog，不要把当前 API 视为冻结接口。
</Warning>
