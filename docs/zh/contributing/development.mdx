## 前置条件

- Python 3.11（贡献检查版本）
- `uv`
- `git`
- 用于仓库搜索的 `rg`

项目命令统一通过 `uv` 运行，不借用父仓库环境。

## 运行测试

```bash
uv run --no-project --python 3.11 \
  --with-editable . \
  --with 'pytest>=7' \
  --with 'pytest-asyncio>=0.23' \
  --with 'openai>=1.66.0' \
  pytest -q
```

## 运行稳定表面 lint 与类型检查

```bash
uv run --no-project --python 3.11 --with-editable . \
  --with 'flake8>=6' flake8 qitos/core qitos/models qitos/trace

uv run --no-project --python 3.11 --with-editable . \
  --with 'mypy>=1' mypy qitos/core qitos/models qitos/trace
```

已退役的 `qitos/engine` 不是检查目标。

## 构建发布 artifact

```bash
uv build
uv run --no-project --python 3.11 --with 'twine>=5.1.1' twine check dist/*
```

## 预览文档

```bash
npx mintlify dev docs
npx mintlify broken-links docs
```

## 常见变更边界

### 新增 Tool

1. 在 canonical `qitos/kit/tool` owner 下实现 Tool。
2. 保持严格输入 schema 与执行逻辑共属一处。
3. 通过显式 `ToolRegistry` 或已维护 Tool set 注册。
4. 按需添加校验、权限、成功、失败、timeout 与 cancelled 行为测试。
5. 支持面变化时更新公开文档。

安全敏感 Tool 必须显式 opt-in，不进入通用 `qitos`、`qitos.kit` 或 quickstart import。

### 修改 Agent runtime

1. 保持 `Message -> Model -> ToolCall -> ToolResult` 契约。
2. Provider SDK 对象停在 adapter 边界。
3. 保持每个调用唯一 terminal `ToolResult`、绝对 deadline、取消和按源顺序提交。
4. 先更新聚焦行为测试，再运行 QitOS 独立全量检查。
5. 在 `CHANGELOG.md` 记录公开或行为变化。

不要恢复 `AgentModule`、Engine、parser/critic、checkpoint 或 recipe 兼容层。Session/Harness 与
Task/Plan 迁移遵循当前架构计划。

### 新增产品 Agent

QitOS 示例应保持小巧，只聚焦一个可复用 kernel 概念。产品级 Agent 与产品插件属于下游应用仓库。

## 发布检查清单

发布前：

1. 运行上述全量 pytest、flake8 与 mypy 命令。
2. 构建包并运行 `twine check`。
3. Mintlify 可用时运行文档死链检查。
4. 确认 README、changelog、公开文档与示例都描述已交付的 Agent 路径。
5. 检查 diff 中没有生成 artifact、凭据或机器本地路径。
