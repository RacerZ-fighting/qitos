# 检查点与分支

QitOS 检查点让你可以在任意步骤保存 Agent 状态，在中断后恢复运行，以及从某个步骤分叉运行来探索替代路径——所有这些都不需要从头重新运行。

这对以下场景至关重要：
- **长时间运行的任务**，可能被中断（网络错误、预算限制）
- **分支实验**，你想从特定步骤探索"如果…会怎样？"
- **时间旅行调试**，你从更早的检查点恢复状态

## Step 1: 基本检查点

创建 `CheckpointStore` 并配置 Engine 使用它：

```python
from qitos.checkpoint import InMemoryCheckpointStore, CheckpointConfig

# 创建内存存储（使用 SqliteCheckpointStore 进行持久化）
store = InMemoryCheckpointStore()

# 传递给 Engine
from qitos.engine import Engine
from my_agent import MyAgent

agent = MyAgent()
engine = Engine(agent, checkpoint_store=store, auto_approve=True)

# 运行 Agent — 检查点自动保存
result = await engine.arun("分析数据集")

# 访问最新检查点
config = CheckpointConfig(thread_id=result.run_id)
latest = await store.get_tuple(config)
print(f"Checkpoint at step {latest.checkpoint.step}")
```

跨会话持久化存储，使用 `SqliteCheckpointStore`：

```python
from qitos.checkpoint import SqliteCheckpointStore

store = SqliteCheckpointStore("./checkpoints.db")
```

## Step 2: 恢复运行

如果运行被中断，从上次检查点恢复：

```python
from qitos.checkpoint import CheckpointConfig

# thread_id 标识运行（通常是 run_id）
config = CheckpointConfig(thread_id="my-run-001")

# 从状态和完整模型历史快照恢复运行
result = await engine.aresume_from_checkpoint(config)
```

Engine 从最新检查点恢复状态，从中断处继续执行。

## Step 3: 分叉检查点

分叉从现有检查点创建新分支，允许你探索替代路径而不影响原始运行：

```python
from qitos.checkpoint import fork_checkpoint, CheckpointConfig

# 指向特定检查点（例如第 3 步）
source_config = CheckpointConfig(
    thread_id="my-run-001",
    checkpoint_id="abc123",  # 要分叉的检查点
)

# 分叉到新线程（真正分支）
fork_config = await fork_checkpoint(
    store,
    source_config,
    new_thread_id="my-run-001-branch-a",
)

# 从分叉状态以不同提示运行 Agent
result = await engine.aresume_from_checkpoint(fork_config)
```

原始运行不受影响。分叉运行从相同状态开始，但可以走不同路径。

## Step 4: 时间旅行（同线程分叉）

如果省略 `new_thread_id`，分叉会在同一线程创建新的检查点并保留原有链路——适用于
"撤销并重试"场景：

```python
from qitos.checkpoint import fork_checkpoint, CheckpointConfig

# 在同一线程内分叉（时间旅行）
config = CheckpointConfig(
    thread_id="my-run-001",
    checkpoint_id="step2-checkpoint-id",
)
time_travel_config = await fork_checkpoint(store, config)

# 从更早状态重新运行
result = await engine.aresume_from_checkpoint(time_travel_config)
```

## Step 5: 持久化边界

全新运行的 `Engine.arun()` 会在第一次 Provider 请求前等待一个 `input` checkpoint，保存已
初始化的任务、状态和历史。之后的完整 step checkpoint 以该输入边界为父级。恢复这个输入
checkpoint 会重新执行 step zero，但不会再次写入 `input` checkpoint。

Engine 也会在每个完整 step 结束后等待 `CheckpointStore.put()`。写入成功前，该 step 不算
持久化完成。SQLite 操作在线程外执行；取消发生时，会先等待正在执行的数据库调用稳定结束，
再继续传播取消。每个 store 实例只属于一个 event loop；内存与 SQLite store 接受相同的 JSON
可序列化数据。

## Step 6: 检查快照

每个 checkpoint 保存恢复和 fork 真正需要的状态、原始任务、完整模型历史前缀与父级链路：

```python
config = CheckpointConfig(thread_id="my-run-001")
tuple_ = await store.get_tuple(config)
print(tuple_.checkpoint.task_text)
print(tuple_.checkpoint.history.messages)
```
