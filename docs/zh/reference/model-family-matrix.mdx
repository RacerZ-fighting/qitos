## 黄金预设

前五个家族（Qwen、Kimi、MiniMax、`gpt-oss`、Gemma 4）是**黄金预设**——QitOS 团队在每次发版时验证得最充分的配置。当你刚上手或需要跑基准对比时，优先选择黄金预设。

其余家族是成熟度不同的**受支持预设**。Anthropic 使用原生 Messages adapter；
OpenAI、Gemini、DeepSeek 与 GLM 仍保留兼容传输，后续可随专用 adapter 演进。

## 查看 Web Tool 能力

配置完成的模型会通过不可变的 `model.capabilities.hosted_tools` 声明已经验证的
Provider-hosted Tool。官方 OpenAI Responses、Qwen Responses/Chat 和官方 Anthropic
Messages 会声明 `web_search`。自定义兼容端点默认保持保守，不会因为使用 Anthropic
协议就继承 Claude 的 server Tool。

Kimi 的 `/search` 与 `$web_search` 继续作为 managed capability 使用。若 Provider 在
输出任何可观察事件前明确拒绝 hosted Web，QitOS 才会回退到同一次准入的 managed
`web_search`；已经输出文本、推理、ToolCall 或原生 item 后不会重放 turn。

## 正确理解这张表

这张表不是模型排行榜。

它表达的是每个家族 preset 选择的 model adapter 与构造默认值。表中 protocol 列是为
现有 artifact 保留的兼容 metadata。最小 Agent loop 不会加载 parser 或执行这些 fallback 链。

如果你需要改某一项，请显式覆盖：

- 用 `build_model_for_preset(protocol=...)` 覆盖兼容标签
- 用 `build_model_for_preset(tool_delivery=...)` 覆盖工具交付方式
- 用 `preset.override()` 扩展预设——参见[家族预设](/zh/concepts/family-presets)

不要把整个示例分叉成另一套实现。
