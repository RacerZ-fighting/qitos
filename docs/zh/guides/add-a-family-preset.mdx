---
title: "如何新增模型家族预设"
description: "在不分叉 Agent runtime 的前提下扩展模型构造默认值。"
---

Family preset 只选择模型构造策略，不会增加新 Agent loop、parser 或产品插件。

新增 preset 前，先回答四个问题：

1. 哪些模型名称应该命中该家族？
2. 使用哪种 Provider transport 构造模型？
3. 如何交付 Tool schema？
4. 哪些上下文、reasoning 与请求默认值已经验证？

## 增加最小 preset

在 `qitos/harness/_presets.py` 中新增一个 `FamilyPreset`：

```python
FamilyPreset(
    id="my-family",
    display_name="My Family",
    model_matchers=("my-family", "my-model-prefix"),
    adapter_kind="openai-compatible",
    default_protocol="legacy-label-v1",
    fallback_protocols=(),
    tool_policy=ToolPolicy(
        primary_delivery="api_parameter",
        fallback_delivery="api_parameter",
        native_tool_call_preferred=True,
    ),
    context_policy=ContextPolicy(
        context_window_hint=128_000,
        fallback_context_window=128_000,
    ),
    recommended_models=("my-family-32b",),
    recommended_temperature=0.2,
)
```

`default_protocol` 和 `fallback_protocols` 是保留的兼容标签。最小 Agent loop 不会
把它们解析为 protocol object、注入 prompt 或运行 fallback parser 链。为 artifact 兼容性使用
稳定的描述性值，不要为了让标签“可执行”而新建 parser。

## 复用 Provider adapter

OpenAI-compatible 端点使用 `OpenAICompatibleAdapter`。只有确实需要对应 wire 契约时，
才使用原生 Anthropic 或 OpenAI adapter。新增模型家族本身不构成新增 transport 的理由。

Adapter 拥有类型化模型事件、原生 Tool call、usage、continuation 与 capability 声明。Preset 只提供
构造默认值。

## 保持结果可检查

`build_model_for_preset(...)` 会把解析后的策略写入 `model.qitos_harness_metadata`。
Adapter 通过 `model.capabilities` 暴露已验证行为。两者都是诊断快照，不是 canonical
Session 状态或恢复真源。

## 验收检查

- `resolve_family_preset(...)` 可以通过家族 id 和目标模型名解析 preset。
- `build_harness_policy(...)` 选中预期 adapter、Tool policy、context policy 与兼容标签。
- `build_model_for_preset(...)` 构造的 Model capability 与已测 Provider 行为一致。
- 原生 Tool call、usage、continuation、取消与失败行为复用现有 adapter 契约测试。
- 只有证据支持时才设置 `recommended_*` 字段。
- `preset.override()` 返回新值，不修改全局状态。
