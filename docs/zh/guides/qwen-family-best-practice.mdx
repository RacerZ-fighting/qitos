对 OpenAI-compatible Qwen 端点，QitOS 优先使用 Provider 的类型化 Tool-call 通道：

```text
Provider ToolCall -> ToolBatchExecutor -> ToolResult -> 下一次模型 turn
```

当前 Agent runtime 不存在 `Decision.act(...)` 转换或文本 parser fallback。Family preset 中的
protocol 名称只保留为兼容 metadata。

## 何时使用原生 Tool call

`qwen` preset 选择 OpenAI-compatible adapter，并把当前准入的 Tool schema 放入 API
请求。如果端点返回 `tool_calls`，adapter 会把 call id 和参数保留为类型化 QitOS
`ToolCall`。

Loop 会对其应用和其他 Provider 相同的校验、权限、deadline、取消与终态结果规则：

- 非法或非 object 参数会带着 `parse_error` 保留在 transcript 中；
- 非法调用永远不执行 Tool；
- 每个调用都会按源顺序得到唯一 terminal `ToolResult`。

如果端点只返回普通文本而没有 Tool call，该文本就是 assistant response。QitOS 不会再通过
已删除的 parser/Decision runtime 重新解释看似结构化的文本。

## 配置 qwen-plus

```python
from qitos.core.agent import Agent
from qitos.harness import build_model_for_preset

model = build_model_for_preset(
    family_id="qwen",
    model_name="qwen-plus",
    api_key="...",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

agent = Agent(model=model, max_turns=8)
```

Preset 贡献模型请求默认值与 metadata。Agent loop 仍在每个 turn 独立冻结实际模型与
Tool exposure。

## 使用 Qwen Web 搜索

当应用准入名为 `web_search` 的 Tool，且 `model.capabilities.hosted_tools` 声明支持时，
Qwen adapter 可以把它投影为 Provider hosted-search 契约：

- Responses 发送 `tools=[{"type": "web_search"}]`。
- Chat Completions 发送 `enable_search: true`。
- 只有 Provider 在任何可观察输出前明确拒绝时，才可回退到已准入的 managed Tool
  schema。

一旦已经出现文本、reasoning、ToolCall delta 或原生 output item，QitOS 就不会 fallback，
避免重放可能已计费或产生外部意义的模型 turn。

需要 client-side managed 实现时，可构造 `QwenWebSearchCapability`。它会把结构化
`search_info.search_results` 和来源 URL 投影成有界 `WebSource`。

## 验证实际边界

```python
print(model.capabilities.native_tool_calls)
print(model.capabilities.hosted_tools)
print(model.qitos_harness_metadata)
```

`model.capabilities` 是 adapter 经测试验证的契约。Preset metadata 说明模型构造方式，
不会启用 parser，也不是 Session 恢复真源。

如果应用生成兼容 trace 目录，`qita` 可以展示 producer 记录的模型与 Tool 事实。
当前 Agent façade 不会自动写入这些 trace artifact。
