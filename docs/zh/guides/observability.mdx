---

`qita` 是 QitOS trace artifact 的只读查看器。它发现已有运行目录、展示已记录的轨迹、
回放事件并导出独立 HTML。qita 不会成为 canonical Session 或 journal owner。

<Warning>
最小 `Agent` loop 尚未自动挂接 `TraceWriter`。不要假设 `agent.prompt(...)` 会创建
`./runs/<run_id>/`。从新 loop/façade 事件流自动生成 trace 属于 Session/Harness
迁移的待完成项。
</Warning>

## 可读取的输入

将 qita 指向包含兼容 trace 运行目录的根目录。历史 artifact 通常包含
`manifest.json`、`events.jsonl` 与 `steps.jsonl`。qita 会校验能够读取的数据；缺少的
provenance 会被标为不完整，不会被猜测补齐。

Agent loop 的 append-only Session journal 是另一种格式，也是模型事务、Tool 终态、
已提交 turn 和 run 终态的 canonical 真源。qita 读取时不会转换或修复这份 journal。

## 看板

```bash
qita board --logdir ./runs
```

默认监听 `http://127.0.0.1:8765`。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--logdir` | `./runs` | 包含兼容 trace 目录的根目录 |
| `--host` | `127.0.0.1` | 绑定地址 |
| `--port` | `8765` | 监听端口 |

```bash
qita board --logdir ./runs --host 0.0.0.0 --port 9000
```

当源 artifact 包含相应数据时，看板会提供搜索、状态筛选、排序、运行元数据、已记录步骤，
以及配对的 Tool call/result 证据。

## 回放

```bash
qita replay --run ./runs/example-run
```

回放只展示一个兼容运行目录中已经持久化的事件。它不是 resume 操作，也不会执行模型或
Tool。

## 导出

```bash
qita export --run ./runs/example-run --html out.html
```

导出的 HTML 会嵌入可读运行数据、CSS 和 JavaScript。分享 artifact 或导出文件前，请先
检查其中是否含有敏感信息。

## 当前边界

- Session journal 是 canonical runtime state。
- qita trace artifact 是观测投影。
- Provider continuation 与 qita index 不是 recovery 真源。
- 最小 loop 的 trace 产出仍待完成；qita 目前可以读取已有的兼容 artifact。
