工具就是智能体可以执行的动作。运行时，Engine 使用 `ToolRegistry` 做精确名称
查找，再由 `ActionExecutor` 完成校验、授权和执行。

## `@tool` 装饰器

使用 `@tool` 把任意可调用对象标记成 QitOS 工具。这个装饰器只会附加元数据，不会改变函数行为，测试里依旧可以像普通函数一样直接调用。

```python
from qitos import tool
from qitos.core.tool import ToolPermission

@tool(
    name="read_file",
    description="Read the contents of a file at the given path.",
    timeout_s=10.0,
    permissions=ToolPermission(filesystem_read=True),
)
def read_file(path: str) -> str:
    with open(path, "r") as f:
        return f.read()
```

### `@tool` 参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `name` | `str \| None` | 在 `Decision.actions` 中使用的工具名。默认是函数 `__name__`。 |
| `description` | `str \| None` | 展示给大模型的工具说明。默认回退到文档字符串。 |
| `group` | `str` | 由应用定义的 exposure 分组。默认是 `"default"`。 |
| `timeout_s` | `float \| None` | 整个 action 的超时，包括预检、重试和实际调用。 |
| `retry_policy` | `RetryPolicy \| None` | 显式调用重试策略；未配置时只执行一次。 |
| `permissions` | `ToolPermission \| None` | 声明该工具需要的系统能力。 |
| `required_ops` | `list[str] \| None` | 环境层面的低级操作能力标识。 |

`ActionExecutor` 是工具重试的唯一责任方。输入校验、权限检查和审批只执行一次，
只有通过预检的实际调用可以重试；所有 attempt 和 backoff 共享工具 timeout 与
Engine 更早的运行 deadline。配置 `RetryPolicy` 时，底层 HTTP/SDK 重试必须关闭。

### `ToolPermission`

`ToolPermission` 描述工具允许做什么。Engine 可以在预检阶段利用这些信息检查环境能力。

```python
from qitos.core.tool import ToolPermission

ToolPermission(
    filesystem_read=True,
    filesystem_write=False,
    network=True,
    command=False,
)
```

四个字段默认都是 `False`。

## ToolRegistry

`ToolRegistry` 是 Engine 分发动作时查询的注册表。通常在 `AgentModule` 构造函数里创建并传入。

```python
from qitos import ToolRegistry

registry = ToolRegistry()
```

### 注册单个工具

用 `registry.register()` 注册一个可调用对象或 `BaseTool` 实例：

```python
@tool(name="add")
def add(a: int, b: int) -> int:
    """Add two integers."""
    return a + b

registry.register(add)
```

也可以在注册时覆写名称或元数据：

```python
from qitos.core.tool import ToolMeta

registry.register(add, name="math.add")
registry.register(some_func, meta=ToolMeta(description="Custom description"))
```

<Warning>
  同一个注册表内工具名必须唯一。重复注册同名工具会抛出 `ValueError`。
</Warning>

### 用 `include` 扫描模块或对象

`registry.include(obj)` 会扫描 `obj` 上所有公开且可调用的属性，并注册其中带有 `@tool` 元数据的成员：

```python
class MyTools:
    @tool(name="summarize")
    def summarize(self, text: str) -> str:
        ...

    @tool(name="translate")
    def translate(self, text: str, lang: str) -> str:
        ...

tools = MyTools()
registry.include(tools)
```

当你把一组相关工具封装成类方法时，这通常是最方便的注册方式。

### 注册工具集

工具集（toolset）指的是任何拥有 `tools()` 方法、并返回可调用对象或 `BaseTool` 列表的对象。使用 `register_toolset()` 注册它：

```python
from qitos.kit import CodingToolSet

registry.register_toolset(
    CodingToolSet(
        workspace_root="/tmp/work",
        include_notebook=False,
        enable_lsp=False,
        enable_tasks=False,
        enable_web=False,
    )
)
```

来自工具集的工具会自动带命名空间：`toolset_name.tool_name`。你也可以显式指定命名空间：

```python
registry.register_toolset(CodingToolSet(workspace_root="/tmp/work"), namespace="coding")
```

### 冻结单个 turn 的工具 exposure

`ToolRegistry` 是由 run 持有、可以变化的完整工具目录。每个模型 turn 开始时，Engine
调用 `AgentModule.build_tool_exposure()` 取得只读 `ToolExposure`。模型 Schema 与动作
分发器共用这一份快照。模型请求进行期间新注册的工具可以在下一 turn 出现，但当前
turn 的分发器不能调用它。

默认 hook 会冻结全部已注册工具。产品需要按 profile、运行能力、Skill 或策略筛选时，
可以覆写它：

```python
class ProductAgent(AgentModule):
    def build_tool_exposure(self, state, tool_registry):
        selected = [
            name
            for name in tool_registry.list_tools()
            if tool_registry.get(name).spec.group in state.enabled_tool_groups
        ]
        return tool_registry.freeze(
            selected,
            metadata={"profile": state.profile},
        )
```

`group` 只负责选择，不代表授权。实际参数仍应交给 `PermissionPipeline` 判断。配置
pipeline 后，它的 allow/deny/ask 结果是唯一准入结论；`needs_approval` 只作为未配置
pipeline 时的后备行为。

每个完成的模型事务都会记录 `prompt_metadata.tool_exposure`，其中包含源 registry
revision、精确工具名、Schema 摘要和应用选择元数据。journal replay 因此可以解释历史
决策实际使用的工具面，而不把当前可变 registry 当作历史真源。

## `BaseTool` 与 `FunctionTool`

如果工具需要维护共享状态或生命周期逻辑，可以直接继承 `BaseTool`：

```python
import asyncio

from qitos.core.tool import BaseTool, ToolSpec, ToolPermission


class DatabaseTool(BaseTool):
    """Query a SQLite database."""

    def __init__(self, db_path: str):
        self.db_path = db_path
        super().__init__(
            ToolSpec(
                name="query_db",
                description="Run a SQL query and return rows as a list.",
                parameters={"sql": {"type": "string", "description": "SQL statement"}},
                required=["sql"],
                permissions=ToolPermission(filesystem_read=True),
            )
        )

    async def execute(self, args: dict, runtime_context: dict | None = None) -> list:
        _ = runtime_context
        sql = str(args["sql"])
        return await asyncio.to_thread(self._query, sql)

    def _query(self, sql: str) -> list:
        import sqlite3
        with sqlite3.connect(self.db_path) as conn:
            return conn.execute(sql).fetchall()


registry.register(DatabaseTool(db_path="data.db"))
```

当你向 `register()` 传入普通可调用对象时，QitOS 内部会自动把它包装成 `FunctionTool`。大多数情况下你无需显式实例化它。

### 严格输入 Schema

每个已注册工具只有一份 canonical `input_schema`。QitOS 会把这份 Schema 原样投影给
模型，并在权限层完成参数调整后、调用 `validate_input()` 或 `execute()` 前，用它校验
最终参数。校验不会做类型强转，例如字符串 `"2"` 不能满足 integer 字段。

自动生成的根对象 Schema 默认带 `additionalProperties: false`，因此未知参数、缺失的
required 字段、错误类型、非法枚举值和 JSON Schema 边界都会被拒绝。确实需要接受任意
根键的工具必须显式声明 `additionalProperties` Schema（或 `true`）。非法 Schema 会在
工具构造时直接失败。

`BaseTool.validate_input()` 继续承载 JSON Schema 无法表达的领域规则，但只有 Schema
校验通过后才会运行。任一校验层失败都不会执行 handler；Schema 失败会生成
`error_category="invalid_tool_arguments"`、`attempts=0`、`executed=false` 的终态结果。

类式工具只有一个异步执行入口：`await execute(args, runtime_context)`。注册表只接受精确的
已注册名称，本身不负责执行；不存在 `run`/`call` 适配、短名称别名、分隔符别名或
大小写修复。需要权限、超时、重试和结果归一化时，应通过 `Engine` 使用
`ActionExecutor`。`read_only=True` 只描述副作用；只有显式
`concurrency_safe=True` 才允许并行。

冻结 turn 时，QitOS 深拷贝 Tool 定义，但保留注册 handler 作为唯一生命周期 owner，因此
schema、timeout、权限和并发元数据不会在本轮漂移，也不会复制有状态计数器、后台 Task、
客户端或清理责任。同步装饰器 callable 仍可兼容，但等待型工作应优先写成 `async def`。

<Note>
  对于实际编码智能体，通常优先使用 `CodingToolSet` 或 `qitos.kit.toolset` 中的预设构建器，而不是手工把文件、Shell、Web 工具逐个注册。
</Note>

## 工具结果契约

普通返回值表示工具成功完成。结构化工具如果还在运行、只得到部分结果，或以非成功
状态结束，应返回统一的生命周期 envelope：

```python
from qitos import ToolResult

return ToolResult(
    status="partial",
    output={"preview": text, "omitted_chars": omitted},
    artifacts=(artifact_ref,),
)
```

规范状态包括 `success`、`partial`、`running`、`error`、`skipped`、`denied`、
`needs_input`、`needs_approval`、`timed_out` 与 `cancelled`。只有精确的 `success`
才计入成功。该边界是严格的：`failed`、`needs_user_input`、
`output_limit_exceeded`、`cancelling` 和 `canceled` 等旧写法会被拒绝，不会再做
兼容归一化；任何未知的显式状态都会被视为错误，而不是猜成成功。

Handler 不需要自行生成关联身份。Engine 会在 Finalizer 前把 canonical Action 的身份写入
`ToolResult.call_id`，因此 Journal replay、History、Reducer 和 trace 始终指向同一个模型 ToolCall。

执行生命周期和业务结果必须分开。例如搜索正常完成但没有匹配项：

```python
return {
    "status": "success",
    "domain_outcome": "no_match",
    "matches": [],
}
```

不要把 `usable`、`pending` 或 `no_match` 放进顶层 `status`。需要用户回答问题时用
`needs_input`，需要执行审批时用 `needs_approval`。即使执行器成功取得了快照，后台
`running` 和 `partial` 仍然不是操作成功终态。

### 持久化长输出

工具可能返回超过模型预算的内容时，为 Engine 配置文件 store：

```python
from qitos import Engine
from qitos.kit import FileArtifactStore

artifacts = FileArtifactStore(
    ".agent/artifacts",
    reference_root=".",
)
engine = Engine(agent, artifact_store=artifacts)
```

Engine 会先保存完整输出，再生成有界模型 replacement。`ToolResult.output` 继续作为
Reducer 与 trace 的 canonical 结果；`ToolResult.artifacts` 保存类型化文件引用，
`model_output` 则是 History 和模型可见事件使用的投影。Checkpoint resume 会重放当时
保存的 History，不会用当前阈值再次截断。

Artifact 目录应位于工具 workspace 内，并把 `reference_root` 指向该 workspace。
模型看到的路径将是 workspace 相对路径，现有 `read_file` 工具可以直接分页读取，
无需再增加 artifact 读取 wrapper。

## 把注册表传给 AgentModule

把准备好的 `ToolRegistry` 传入 `AgentModule.__init__()`：

```python
from qitos import AgentModule, ToolRegistry, tool


class SearchAgent(AgentModule[MyState, dict, Action]):
    def __init__(self):
        registry = ToolRegistry()
        registry.register(web_search)
        registry.register(read_file)
        super().__init__(tool_registry=registry)
```

Engine 会在每个 turn 冻结 `agent.tool_registry`，并用同一份 exposure 创建该 turn 的
`ActionExecutor`。你也可以调用 `registry.get_tool_descriptions()` 检查完整注册目录：

```python
def build_system_prompt(self, state: MyState) -> str | None:
    tools_text = self.tool_registry.get_tool_descriptions()
    return f"You have access to these tools:\n\n{tools_text}"
```

## 完整示例

<CodeGroup>
```python tools.py
from qitos import tool, ToolPermission

@tool(
    name="read_file",
    timeout_s=5.0,
    permissions=ToolPermission(filesystem_read=True),
)
def read_file(path: str) -> str:
    """Read the contents of a file."""
    with open(path) as f:
        return f.read()


@tool(
    name="write_file",
    timeout_s=5.0,
    permissions=ToolPermission(filesystem_write=True),
)
def write_file(path: str, content: str) -> str:
    """Write content to a file."""
    with open(path, "w") as f:
        f.write(content)
    return f"Written {len(content)} bytes to {path}"
```

```python agent.py
from dataclasses import dataclass
from typing import Any

from qitos import AgentModule, StateSchema, ToolRegistry

from .tools import read_file, write_file


@dataclass
class EditorState(StateSchema):
    files_read: list[str] = None

    def __post_init__(self):
        if self.files_read is None:
            self.files_read = []


class EditorAgent(AgentModule[EditorState, dict[str, Any], Any]):
    def __init__(self, llm):
        registry = ToolRegistry()
        registry.register(read_file)
        registry.register(write_file)
        super().__init__(tool_registry=registry, llm=llm)

    def init_state(self, task: str, **kwargs: Any) -> EditorState:
        return EditorState(task=task, max_steps=int(kwargs.get("max_steps", 10)))

    def build_system_prompt(self, state: EditorState) -> str | None:
        return (
            "You are a file editor.\n\n"
            f"Tools:\n{self.tool_registry.get_tool_descriptions()}"
        )

    def reduce(self, state: EditorState, observation: dict, decision) -> EditorState:
        for action in decision.actions:
            if action.name == "read_file":
                state.files_read.append(action.args.get("path", ""))
        if decision.final_answer:
            state.final_result = decision.final_answer
        return state
```
