---
title: "Trace artifact"
description: "使用只读 qita 工具检查兼容的 QitOS trace 目录。"
---

QitOS 保留现有 trace 目录格式作为兼容与检查界面。`qita` 可以读取早期版本或
应用显式 trace producer 产生的目录：

```text
<trace_logdir>/<run_id>/
  manifest.json
  events.jsonl
  steps.jsonl
```

<Warning>
当前 `Agent` façade 不会自动连接 `TraceWriter`。新的 Agent run 可以通过
`SessionJournal` 记录 loop 事务，但除非应用提供 producer，否则不会生成这三个
trace 文件。Trace artifact 不是 Session 恢复真源。
</Warning>

## 文件含义

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | Run 摘要与 producer 写入的复现元信息 |
| `events.jsonl` | Trace producer 记录的事件流 |
| `steps.jsonl` | 已完成的旧 step 记录 |

对单个 trace 目录而言，这些文件是 `qita` 展示的证据。它们不会替代 canonical
Session Journal，也不能创建可执行的 resume 或 fork。

旧 artifact 可能包含 `prompt_protocol`、`parser_name`、`run_spec`、
`experiment_spec` 或 benchmark metadata。这些字段只描述写入该 artifact 的
producer，不会在当前 Agent 路径中启用 parser、Decision/Action lifecycle、
benchmark runner 或 Engine。

## 检查兼容 artifact

```bash
qita board --logdir ./runs
qita replay --run ./runs/<run_id>
qita export --run ./runs/<run_id> --html ./report.html
```

这些命令用于审阅、比较和导出现有证据。远程模型与外部环境仍具有不确定性，因此
artifact replay 是检查操作，不是确定性重新执行。

要从安全边界继续 Run，应在权威 Session/Harness 迁移暴露该工作流后使用
canonical Session Journal。复制或修改 trace 目录永远不会创建可恢复 Run。
