QitOS 可以为每个 Run 保存一份 append-only JSONL Journal。启用后，它是模型历史、工具事务、
状态恢复、resume 和 fork 的唯一真源。同一个 Engine 不得同时配置 checkpoint store。

每个 Journal 实例都是唯一的存储 owner。`create()` 或 `open()` 会取得该 Run 的操作系统级
writer lease；其他进程或 Engine 若尝试同时写入，会得到 `JournalOwnershipError`，而不是打开
第二个 writer。`Engine.arun()` 和 `Engine.aresume_from_journal()` 会在所有终止路径关闭其
Journal。关闭后的实例永久拒绝修改，但仍可从隔离的内存值 replay 或查询已提交工具事务，便于诊断。

## 工具事务顺序

Engine 按以下顺序写入：

1. `model.completed`
2. `tool.started`
3. 执行 Handler
4. 生成唯一 canonical `ToolResult`
5. `tool.terminal`
6. 将结果归约到 working state
7. `step.committed`

`tool.started` 是持久化执行许可；写入失败时不能执行 Handler。Finalizer 生成的 terminal result
只持久化一次，History 和 Reducer 使用同一个值。多调用 batch 中，每个 terminal 会先完成 Reducer，
再生成下一个结果；显式声明并发安全的 Handler 仍可并发执行。

Finalizer 或 Reducer 失败会中止当前未提交事务。恢复只依据 durable started/terminal 边界，
不会在缺少结果时发布 step。

恢复时，如果只有 `tool.started` 而没有 `tool.terminal`，Engine 会补写一个“副作用未知”的明确
error 终态，绝不重放 Handler。没有获得 `tool.started` 的调用会补成“无副作用”的 cancelled 终态。
如果 terminal 已完整而 `step.committed` 缺失，恢复只重跑纯 Reducer。

Engine 会在 Finalizer 前从 canonical Action 绑定 `ToolResult.call_id`，replay 时继续校验同一
身份；旧 terminal 记录没有该字段时，会从相邻 Action 恢复，不需要迁移 Journal。

## Root/Child 共享预算

默认情况下 Engine 创建并拥有一个 `BudgetLedger`；产品运行时也可以把 Root 的 ledger 传给
每个 Child Engine，让完整 Run tree 共同消耗一份 token 与 cost 额度。每个 Engine 自己的
`RuntimeBudget` 仍是本地上限，因此 Child 可以更严格，但不能获得第二份全局额度。

Provider 事务完成后，Engine 会先向 Root JSONL append 一条幂等的 `budget.committed`，再推进
内存总账。记录包含来源 Run、模型事务、token/cost 用量以及完整性。Root resume 与 fork 只从
这些 canonical JSONL 记录重建共享总量，不依赖 SQLite。旧 Journal 没有预算记录时，会从
`model.completed` 恢复 Root 用量，并从 `child.terminal` 恢复已完成 Child 的用量。

`EngineResult.total_*` 表示共享 Run 总量，`local_total_*` 表示当前 Engine 自身用量；
`ChildResult` 始终保存 Child 本地值，Parent 不应再次把它加回总账。本地估算 token 仍会消耗
额度，但会把 usage 标记为 incomplete；cost 完整还要求显式 pricing 和可用的输入/输出计数。

首版会串行结算，但不会在 Provider 请求前预留估算额度。已经通过准入的并发请求可能一起越过
上限；总量达到限制后，下一 turn 会停止。

## 状态提交

`step.committed` 保存带前后摘要的确定性 JSON Patch 子集。该记录 durable 之前，Engine 只暴露上
一个提交态。初始、周期和终态 snapshot 只用于加速 replay，不是第二份真源。

JSONL writer 会等待每条记录 durable 后返回。Darwin 使用 `F_FULLFSYNC`，其他 POSIX 系统优先
使用 `fdatasync`。

canonical 文件旁的 `journal.index.sqlite3` 只是可丢弃的读取投影。QitOS 只在 JSONL 写入 durable
后更新它；投影缺失、过期、损坏或 schema 不受支持时，会从已验证的 JSONL 记录重建。投影失败
不会让 canonical append 失败或回滚。open 和 replay 始终先解析 canonical JSONL，SQLite 不提供
replay record；只有逐条摘要与 canonical record 一致时才会保留该投影。删除 SQLite 文件不会
丢失 Run 状态。语法完整但 schema 未知或语义无效的 JSONL 记录会 fail closed；恢复时只截断
语法未完成的 torn tail。

`JsonlRunCatalog` 是这条边界的只读侧。即使 writer lease 仍由运行中的 Engine 持有，它也能检查、
列出 Run，并在不构造 Agent 的情况下校验祖先与直接 Child lineage。Catalog 优先读取与 canonical
文件完全一致的 SQLite 投影，否则只读取当前完整的 JSONL 前缀；它不会取得 writer lease、修复
torn tail 或重建任何 artifact。`RunStatus.RESUMABLE` 只表示没有 durable `run.completed`，并不
声称当前一定有 Engine 进程在运行。

```python
from qitos import Engine
from qitos.kit.journal import JsonlRunCatalog, JsonlSessionJournal

journal = JsonlSessionJournal(".qitos/sessions")
result = await Engine(agent=agent, journal=journal).arun("inspect the project")

resumed = await Engine(
    agent=agent,
    journal=JsonlSessionJournal(".qitos/sessions"),
).aresume_from_journal(result.run_id)

catalog = JsonlRunCatalog(".qitos/sessions")
handle = await catalog.inspect_run(result.run_id)
all_runs = await catalog.list_runs()
ancestors = await catalog.lineage(result.run_id)
```

Fork 只接受 committed `JournalPosition`。Child Journal 拥有独立的继承前缀，不会修改 Parent。
继承到本 Run 的 committed record 也能成为下一次 fork 的本地边界，因此 fork 后可以继续 fork，
并且后代无需祖先文件也能恢复。直接调用 `SessionJournal.fork()` 会保留两边 open；
`Engine.afork_journal()` 会关闭 source，并把 open Child 交给调用方。每个 open Journal 都由调用方
持有，直至 Engine 消费它或显式调用 `close()`。

## 查询已提交的工具事务

每个 canonical action result 在 terminal durable 后都会带有 `JournalRecordRef`。应用若需要在
history 压缩后继续定位结果，只在状态里保存这个轻量 origin locator：

```python
from qitos.core.journal import JournalRecordRef

reference = JournalRecordRef(run_id=origin_run_id, record_id=terminal_record_id)
transaction = journal.find_tool_transaction(reference)
if transaction is not None:
    result = transaction.result
```

该查询只读，并且仅在 `step.committed` 已发布 terminal 后返回一份新的、类型化的
`ToolTransaction`。打开 Journal 时，查询视图会从 canonical JSONL 重建。Fork 使用 Parent 的
origin reference 解析继承结果，不把 ToolResult 复制到第二个存储。未知、未提交或改写成 Child
run id 的引用都返回 `None`。

Run Mailbox 使用 `runtime_input.posted` 持久化外部输入，并用
`model.completed.runtime_input_ids` 记录模型已经消费的 event id。后台 Child 与后台进程的完成输入则可
由本 Run 的 `child.terminal` / `process.terminal` 确定性重建；`child.started` 会记录是否后台执行，
因此前台 Child 的 ToolResult 不会在 resume 后被 Mailbox 重复投递。如果进程在 terminal durable 后、
`runtime_input.posted` 前退出，resume 会补回同一个稳定事件；已有消费记录时不会重复投递。Fork
不会把继承来的 Parent terminal 或 pending input 变成自己的输入。

Child 在构造 Engine 前写入 `child.started`，在通知 Parent 前写入 `child.terminal`。Resume 会恢复
终态，并把缺少 terminal 的 started Child 补成 `interrupted`；恢复期间新生成的 terminal 也会在
inbox 打开前进入投影。QitOS 不会重新连接或重放 Child Engine，Fork 也不获得 Parent Handle 的
控制权。终态 Child 的 follow-up 恢复仍由应用层 Session 负责。
