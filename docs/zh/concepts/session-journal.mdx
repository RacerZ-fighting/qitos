title: Session Journal
description: 持久化完整模型与工具事务，并支持恢复和分叉。
---

QitOS 可以为每个 Run 保存一份 append-only JSONL Journal。启用后，它是模型历史、工具事务、
状态恢复、resume 和 fork 的唯一真源。同一个 Engine 不得同时配置 checkpoint store。

每个 Journal 实例都是唯一的存储 owner。`create()` 或 `open()` 会取得该 Run 的操作系统级
writer lease；其他进程或 Engine 若尝试同时写入，会得到 `JournalOwnershipError`，而不是打开
第二个 writer。`Engine.arun()` 和 `Engine.aresume_from_journal()` 会在所有终止路径关闭其
Journal。关闭后的实例永久拒绝修改，但仍可从隔离的内存值 replay 或查询已提交工具事务，便于诊断。

## 工具事务顺序

Engine 按以下顺序写入：

1. `model.completed`
2. `tool.started`
3. 执行 Handler
4. 生成唯一 canonical `ToolResult`
5. `tool.terminal`
6. 将结果归约到 working state
7. `step.committed`

`tool.started` 是持久化执行许可；写入失败时不能执行 Handler。Finalizer 生成的 terminal result
只持久化一次，History 和 Reducer 使用同一个值。多调用 batch 中，每个 terminal 会先完成 Reducer，
再生成下一个结果；显式声明并发安全的 Handler 仍可并发执行。

Finalizer 或 Reducer 失败会中止当前未提交事务。恢复只依据 durable started/terminal 边界，
不会在缺少结果时发布 step。

恢复时，如果只有 `tool.started` 而没有 `tool.terminal`，Engine 会补写一个“副作用未知”的明确
error 终态，绝不重放 Handler。没有获得 `tool.started` 的调用会补成“无副作用”的 cancelled 终态。
如果 terminal 已完整而 `step.committed` 缺失，恢复只重跑纯 Reducer。

## 状态提交

`step.committed` 保存带前后摘要的确定性 JSON Patch 子集。该记录 durable 之前，Engine 只暴露上
一个提交态。初始、周期和终态 snapshot 只用于加速 replay，不是第二份真源。

JSONL writer 会等待每条记录 durable 后返回。Darwin 使用 `F_FULLFSYNC`，其他 POSIX 系统优先
使用 `fdatasync`。

canonical 文件旁的 `journal.index.sqlite3` 只是可丢弃的读取投影。QitOS 只在 JSONL 写入 durable
后更新它；投影缺失、过期、损坏或 schema 不受支持时，会从已验证的 JSONL 记录重建。投影失败
不会让 canonical append 失败或回滚。open 和 replay 始终先解析 canonical JSONL，SQLite 不提供
replay record；只有逐条摘要与 canonical record 一致时才会保留该投影。删除 SQLite 文件不会
丢失 Run 状态。语法完整但 schema 未知或语义无效的 JSONL 记录会 fail closed；恢复时只截断
语法未完成的 torn tail。

```python
from qitos import Engine
from qitos.kit.journal import JsonlSessionJournal

journal = JsonlSessionJournal(".qitos/sessions")
result = await Engine(agent=agent, journal=journal).arun("inspect the project")

resumed = await Engine(
    agent=agent,
    journal=JsonlSessionJournal(".qitos/sessions"),
).aresume_from_journal(result.run_id)
```

Fork 只接受 committed `JournalPosition`。Child Journal 拥有独立的继承前缀，不会修改 Parent。
Fork 会关闭 source Journal，并返回仍处于 open 状态的 Child；接收 Child 的调用方负责其生命周期，
直至 Engine run 消费它或显式调用 `close()`。

## 查询已提交的工具事务

每个 canonical action result 在 terminal durable 后都会带有 `JournalRecordRef`。应用若需要在
history 压缩后继续定位结果，只在状态里保存这个轻量 origin locator：

```python
from qitos.core.journal import JournalRecordRef

reference = JournalRecordRef(run_id=origin_run_id, record_id=terminal_record_id)
transaction = journal.find_tool_transaction(reference)
if transaction is not None:
    result = transaction.result
```

该查询只读，并且仅在 `step.committed` 已发布 terminal 后返回一份新的、类型化的
`ToolTransaction`。打开 Journal 时，查询视图会从 canonical JSONL 重建。Fork 使用 Parent 的
origin reference 解析继承结果，不把 ToolResult 复制到第二个存储。未知、未提交或改写成 Child
run id 的引用都返回 `None`。

后台任务、Mailbox、Child 生命周期和交互输入目前还不能从 Journal 恢复。
