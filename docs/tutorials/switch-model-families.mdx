---
title: "Switch model families with presets"
description: "Run the same Agent façade with different model-family construction defaults."
---

Family presets select a Provider adapter and model request defaults without changing
the minimal Agent loop. They do not install a parser or a second execution runtime.

## Step 1 — Build a model with a preset

```python
from qitos.harness import build_model_for_preset

model = build_model_for_preset(
    family_id="qwen",
    model_name="Qwen/Qwen3-8B",
    api_key="...",
    base_url="https://api.siliconflow.cn/v1/",
)
```

The returned object implements the ordinary QitOS Model contract. The preset chooses
the adapter, request and reasoning defaults, Tool delivery policy, and context-window
hints. Provider adapters still deliver typed assistant messages and native Tool calls
to the same loop.

`default_protocol` and `fallback_protocols` remain compatibility labels in
`qitos_harness_metadata`. The current Agent loop does not load a parser or inject an
output protocol from those labels.

## Step 2 — Run the same Agent composition

Only model construction changes:

```python
import asyncio

from qitos.core.agent import Agent
from qitos.harness import build_model_for_preset


async def main() -> None:
    configs = [
        ("qwen", "Qwen/Qwen3-8B", "https://api.siliconflow.cn/v1/"),
        ("kimi", "moonshot-v1-128k", "https://api.moonshot.ai/v1/"),
        ("deepseek", "deepseek-chat", "https://api.deepseek.com/v1/"),
    ]

    for family_id, model_name, base_url in configs:
        model = build_model_for_preset(
            family_id=family_id,
            model_name=model_name,
            api_key="...",
            base_url=base_url,
        )
        agent = Agent(model=model, max_turns=1)
        result = await agent.prompt("Reply with the model family in one sentence.")
        print(family_id, result.status.value)


asyncio.run(main())
```

Use the appropriate credential for each Provider in real code. Do not place API keys
in source files.

## Step 3 — Override immutable defaults

```python
from dataclasses import replace
from qitos.harness import resolve_family_preset

qwen = resolve_family_preset("qwen")
custom_qwen = qwen.override(
    context_policy=replace(qwen.context_policy, context_window_hint=256_000),
    notes="Extended context variant for long-horizon tasks",
)
```

`override()` returns a new `FamilyPreset`; it does not mutate process-global state.
Pass the fields you need to `build_model_for_preset(...)` when constructing the actual
model.

## Step 4 — Inspect available presets

```bash
qit bench presets
```

The command prints preset identities, adapter kinds, Tool delivery policies, context
hints, and compatibility labels. Those labels are diagnostic metadata, not an active
fallback parser chain.

The `recommended_*` fields are also advisory. The Agent façade does not automatically
apply step, token, retry, or temperature recommendations; applications choose their
own run budgets and pass model request options explicitly.

## Step 5 — Compare the effective model boundary

Inspect `model.capabilities` and `model.qitos_harness_metadata` before a run:

```python
print(model.capabilities)
print(model.qitos_harness_metadata)
```

Capabilities describe behavior proven by the selected adapter. Harness metadata
records how the preset was resolved. Neither object is Session recovery truth.

If an application also emits a compatible trace artifact, read-only `qita` can compare
the producer-recorded model metadata. The current Agent façade does not emit those
trace directories automatically.
