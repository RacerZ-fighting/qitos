---
title: "Add a model-family preset"
description: "Extend model construction defaults without forking the Agent runtime."
---

A family preset selects model-construction policy. It does not add a new Agent loop,
parser, or product plugin.

Before adding one, answer four questions:

1. Which model names resolve to this family?
2. Which Provider transport constructs the model?
3. How are Tool schemas delivered?
4. Which context, reasoning, and request defaults have been verified?

## Add the smallest preset

Add one `FamilyPreset` entry in `qitos/harness/_presets.py`:

```python
FamilyPreset(
    id="my-family",
    display_name="My Family",
    model_matchers=("my-family", "my-model-prefix"),
    adapter_kind="openai-compatible",
    default_protocol="legacy-label-v1",
    fallback_protocols=(),
    tool_policy=ToolPolicy(
        primary_delivery="api_parameter",
        fallback_delivery="api_parameter",
        native_tool_call_preferred=True,
    ),
    context_policy=ContextPolicy(
        context_window_hint=128_000,
        fallback_context_window=128_000,
    ),
    recommended_models=("my-family-32b",),
    recommended_temperature=0.2,
)
```

`default_protocol` and `fallback_protocols` are retained compatibility labels. The
minimal Agent loop does not resolve them to protocol objects, inject prompts, or run a
fallback parser chain. Use a descriptive stable value for artifact compatibility; do
not add a parser to make the label executable.

## Reuse Provider adapters

Use `OpenAICompatibleAdapter` for an OpenAI-compatible endpoint. Use the native
Anthropic or OpenAI adapter only when its wire contract is the behavior you need.
Adding a model family is not, by itself, a reason to add a new transport.

The adapter owns typed model events, native Tool calls, usage, continuation, and
capability reporting. A preset only supplies construction defaults.

## Keep the result inspectable

`build_model_for_preset(...)` attaches the resolved policy to
`model.qitos_harness_metadata`. The adapter exposes its tested behavior through
`model.capabilities`. Both are diagnostic snapshots; neither is canonical Session
state or recovery truth.

## Validation checklist

- `resolve_family_preset(...)` resolves both the family id and intended model names.
- `build_harness_policy(...)` selects the intended adapter, Tool policy, context policy,
  and compatibility labels.
- `build_model_for_preset(...)` constructs a Model whose capabilities match the tested
  Provider behavior.
- Native Tool-call, usage, continuation, cancellation, and failure behavior use the
  existing adapter contract tests.
- `recommended_*` fields are set only when evidence supports the recommendation.
- `preset.override()` returns a new value without mutating global state.
