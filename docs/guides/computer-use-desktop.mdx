---
title: "Computer use and DesktopEnv"
description: "Compose QitOS desktop environment and GUI Tool primitives with the current Agent façade."
---

QitOS provides reusable desktop primitives rather than a second computer-use runtime:

- `DesktopEnv` for screenshot, accessibility, terminal, and GUI-controller operations;
- `qitos.kit.tool.gui` for atomic GUI Tools;
- `ComputerUseToolSet` and `computer_use_tools()` for explicit Tool registration;
- typed `UserMessage` image blocks for Provider-neutral multimodal input.

The current Agent loop consumes typed messages and native Provider Tool calls. It does
not load `desktop_actions_*` protocols, text parsers, or `Decision` objects.

## Build an environment and Tool registry

```python
from qitos.kit.env import DesktopEnv
from qitos.kit.toolset import computer_use_tools

env = DesktopEnv.from_mock(
    screenshot_path="screen.png",
    instruction="Click the visible Continue button.",
    accessibility_tree={"role": "window", "name": "Demo"},
)
registry = computer_use_tools()
```

The GUI Tools resolve `gui_controller` operations from the Agent's runtime `env`. The
application still owns environment setup, reset, teardown, authorization, and the
projection of each fresh observation into the next user message.

```python
from qitos.core.agent import Agent

agent = Agent(model=model, tool_registry=registry, env=env, max_turns=8)
```

Do not treat `env=env` as automatic observation polling. Capture the observation at an
application safe point and construct a typed multimodal message; see
[Multimodal messages](/guides/multimodal-core).

## Atomic GUI actions

The Tool set exposes pointer, keyboard, scroll, wait, done, and fail actions. They use
the same Tool validation, permission, deadline, cancellation, and terminal-result
contract as other QitOS Tools. Tool execution is serial unless a Tool explicitly
declares safe concurrency; GUI actions do not.

## Current boundary

QitOS does not claim an end-to-end OSWorld runner, an automatic screenshot-observe
loop, or a provider-specific computer-use API. Applications compose those policies
around the same `Agent` façade and keep product/benchmark behavior outside the kernel.

`qita` can still inspect compatible screenshot-backed trace artifacts produced by an
older runtime or an explicit application-side producer. New façade runs do not emit
those trace directories automatically.
