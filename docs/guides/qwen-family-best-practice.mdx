---
title: "Qwen family best practice"
description: "Run Qwen and qwen-plus through typed native Tool calls in the minimal Agent loop."
---

For OpenAI-compatible Qwen endpoints, QitOS prefers the Provider's typed Tool-call
channel:

```text
Provider ToolCall -> ToolBatchExecutor -> ToolResult -> next model turn
```

There is no `Decision.act(...)` conversion or text-parser fallback in the current
Agent runtime. Family-preset protocol names remain compatibility metadata only.

## When native Tool calls are available

The `qwen` preset selects the OpenAI-compatible adapter and sends admitted Tool schemas
through the API request. If the endpoint returns `tool_calls`, the adapter preserves
their call ids and arguments as typed QitOS `ToolCall` values.

The loop then applies the same validation, permission, deadline, cancellation, and
terminal-result rules as every other Provider:

- malformed or non-object arguments remain in the transcript with `parse_error`;
- malformed calls never execute a Tool;
- every call receives one terminal `ToolResult` in source order.

If the endpoint returns ordinary text without Tool calls, that text is an assistant
response. QitOS does not reinterpret structured-looking text through the removed
parser/Decision runtime.

## Configure qwen-plus

```python
from qitos.core.agent import Agent
from qitos.harness import build_model_for_preset

model = build_model_for_preset(
    family_id="qwen",
    model_name="qwen-plus",
    api_key="...",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

agent = Agent(model=model, max_turns=8)
```

The preset contributes model request defaults and metadata. The Agent loop still
freezes the actual model and Tool exposure independently for each turn.

## Use Qwen Web search

When your application admits a Tool named `web_search`, the Qwen adapter can project it
to the Provider's hosted-search contract when `model.capabilities.hosted_tools`
declares support:

- Responses sends `tools=[{"type": "web_search"}]`.
- Chat Completions sends `enable_search: true`.
- An explicit Provider rejection before any observable output may fall back to the
  admitted managed Tool schema.

QitOS never performs that fallback after text, reasoning, ToolCall deltas, or native
output items become observable. This prevents replaying a model turn after it may have
already produced a billable or externally meaningful result.

For a client-side managed implementation, construct `QwenWebSearchCapability`. It
projects structured `search_info.search_results` and source URLs into bounded
`WebSource` values.

## Verify the effective boundary

```python
print(model.capabilities.native_tool_calls)
print(model.capabilities.hosted_tools)
print(model.qitos_harness_metadata)
```

`model.capabilities` is the adapter's tested contract. Preset metadata explains model
construction but does not activate a parser or become Session recovery truth.

If an application produces a compatible trace directory, `qita` can display the
producer-recorded model and Tool facts. The current Agent façade does not write those
trace artifacts automatically.
