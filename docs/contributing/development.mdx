## Prerequisites

- Python 3.11 for contributor checks
- `uv`
- `git`
- `rg` for repository search

Run project commands through `uv`; do not borrow a parent repository environment.

## Run the test suite

```bash
uv run --no-project --python 3.11 \
  --with-editable . \
  --with 'pytest>=7' \
  --with 'pytest-asyncio>=0.23' \
  --with 'openai>=1.66.0' \
  pytest -q
```

## Run stable-surface lint and type checks

```bash
uv run --no-project --python 3.11 --with-editable . \
  --with 'flake8>=6' flake8 qitos/core qitos/models qitos/trace

uv run --no-project --python 3.11 --with-editable . \
  --with 'mypy>=1' mypy qitos/core qitos/models qitos/trace
```

The retired `qitos/engine` package is not a check target.

## Build release artifacts

```bash
uv build
uv run --no-project --python 3.11 --with 'twine>=5.1.1' twine check dist/*
```

## Preview documentation

```bash
npx mintlify dev docs
npx mintlify broken-links docs
```

## Common change boundaries

### Add a Tool

1. Implement the Tool under its canonical `qitos/kit/tool` owner.
2. Keep strict input schema and execution together.
3. Register it through an explicit `ToolRegistry` or maintained Tool set.
4. Add behavior tests for validation, permission, success, failure, timeout, and
   cancellation as applicable.
5. Update public documentation when the supported surface changes.

Security-sensitive Tools require explicit opt-in imports. They do not enter generic
`qitos`, `qitos.kit`, or quickstart imports.

### Change the Agent runtime

1. Preserve the `Message -> Model -> ToolCall -> ToolResult` contract.
2. Keep Provider SDK objects at the adapter boundary.
3. Preserve one terminal `ToolResult` per call, absolute deadlines, cancellation, and
   source-ordered results.
4. Update focused behavior tests, then run the full independent QitOS checks.
5. Record public or behavioral changes in `CHANGELOG.md`.

Do not restore `AgentModule`, Engine, parser/critic, checkpoint, or recipe compatibility
layers. Session/Harness and Task/Plan migration follows the active architecture plan.

### Add a product Agent

Keep QitOS examples small and focused on one reusable kernel concept. Product-grade
agents and product plugins belong in downstream application repositories.

## Release checklist

Before a release:

1. Run the full pytest, flake8, and mypy commands above.
2. Build the package and run `twine check`.
3. Run the documentation broken-link check when Mintlify is available.
4. Confirm README, changelog, public docs, and examples describe the shipped Agent path.
5. Review the diff for generated artifacts, credentials, and machine-local paths.
