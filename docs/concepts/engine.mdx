title: "Engine"
description: "Engine is the execution kernel that owns the agent loop: it calls your AgentModule hooks in sequence, executes actions, manages tracing, and enforces stop criteria."
---

`Engine` is the single execution kernel for all QitOS agent workflows. It runs the step loop, coordinates your `AgentModule` hooks, dispatches tool calls to the `ToolRegistry` for execution, applies critics (post-step evaluators that can approve, stop, or retry the step), checks stop conditions, and writes trace artifacts (persistent records like `steps.jsonl` and `events.jsonl` that capture what happened during the run). You interact with it directly only when you need control beyond what `agent.run()` provides.

<Note>
  QitOS enforces a **single-kernel rule**: there is exactly one `Engine` per run. Extensions like parsers, critics, memory adapters, and toolkits attach to this pipeline — they do not introduce a second execution loop.
</Note>

## How the loop works

Each step follows a fixed sequence:

```
safe-point input → capture turn → decide → act → reduce → critics → check_stop → commit
```

1. **safe-point input** — queued runtime events are projected before the next model
   transaction, never in the middle of a turn.
2. **capture turn** — Engine creates an immutable `TurnSnapshot` containing the exact
   model, protocol, complete History view, Tool exposure, runtime capabilities,
   deadline, pricing, and remaining budgets shared by model projection and dispatch.
3. **prepare** — `agent.prepare_turn(state, observation, turn)` formats state into the
   model-ready prompt text. Its default delegates to `prepare(state)`.
4. **decide** — `agent.decide(state, observation)` is checked first; if it returns
   `None`, the Engine calls the async Provider path.
5. **act** — Tool calls are admitted and awaited through the frozen Tool exposure.
   Explicitly concurrency-safe calls may overlap; terminal results commit in input order.
6. **reduce** — `agent.reduce(state, observation, decision)` updates state with the new observation.
7. **critics** — Optional post-step evaluators can stop or request another turn.
8. **check_stop** — Completion policy, budgets, `agent.should_stop()`, and custom criteria are evaluated.
9. **commit** — Journal state, trace records, and safe snapshots advance only after the
   complete transaction is ready.

`Engine.arun()` and `Engine.astep()` both delegate this sequence to the same turn
transaction. The outer Engine owns Run setup, safe-point admission, budget/cancellation
checks, and cleanup; it does not maintain a second step implementation. Provider
transport and request projection remain in the model runtime, while response-to-
`Decision` parsing is a composed decision runtime. Critics and handoff are optional
control policies around the transaction rather than alternate Agent loops.

## Constructor

```python
from qitos import Engine

engine = Engine(
    agent=agent,
    budget=RuntimeBudget(max_steps=20),
    parser=ReActTextParser(),
    critics=[my_critic],
    stop_criteria=[FinalResultCriteria()],
    env=host_env,
    trace_writer=trace_writer,
    hooks=[my_hook],
)
```

| Parameter          | Type                        | Description                                                                 |
| ------------------ | --------------------------- | --------------------------------------------------------------------------- |
| `agent`            | `AgentModule`               | **Required.** The policy module to execute.                                 |
| `budget`           | `RuntimeBudget \| None`     | Step/time/token/cost/Tool/Child limits. Defaults to `RuntimeBudget(max_steps=10)`. |
| `model_pricing`    | `ModelPricing \| None`      | Explicit USD-per-million prices required when a cost budget is configured. |
| `journal`          | `SessionJournal \| None`    | Canonical per-Run transaction journal; mutually exclusive with checkpoints. |
| `parser`           | `Parser \| None`            | Parses raw model output into a `Decision`. Must match your prompt format.   |
| `critics`          | `list[Critic] \| None`      | Post-step evaluators that can stop or retry a step.                         |
| `stop_criteria`    | `list[StopCriteria] \| None`| Stop conditions. Defaults to `[FinalResultCriteria()]`.                     |
| `env`              | `Env \| None`               | Environment providing `reset/observe/step/is_terminal/close`.               |
| `trace_writer`     | `TraceWriter \| None`       | Writes `manifest.json`, `events.jsonl`, `steps.jsonl` for this run.         |
| `hooks`            | `list[EngineHook] \| None`  | Hook instances called on lifecycle events.                                  |
| `render_hooks`     | `list \| None`              | Render hooks (e.g., terminal UI). Appended to `hooks` internally.           |
| `history_policy`   | `HistoryPolicy \| None`     | Controls how the in-run conversation history is managed.                    |
| `recovery_policy`  | `RecoveryPolicy \| None`    | Controls how the Engine responds to step failures.                          |

<Tip>
  Prefer calling `agent.run()` for single-run workflows. Use `Engine` directly when you need to reuse an Engine across multiple runs or configure hooks dynamically between runs.
</Tip>

## Runtime input and idle wait

Long-running tools can return a handle before their work finishes. Use
`RuntimeInput` to notify the same Engine run when that work reaches a terminal
state:

```python
from qitos import RuntimeInput

accepted = engine.post_runtime_event(
    RuntimeInput(
        event_id="command:42:terminal",
        kind="command.terminal",
        correlation_id="42",
        source="shell",
        payload={"status": "completed", "exit_code": 0},
    ),
    run_id=run_id,
)
```

Capture `run_id` from `engine.active_run_id` after the run starts. A post returns
`False` when the event id is a duplicate, the run id does not match, or the run
has ended. Keep event payloads small. Store full command output behind the tool's
normal result or read API.

An agent can explicitly enter idle wait with
`Decision.wait(meta={"runtime_wait": True})`. JSON decision agents can return:

```json
{"mode":"wait","runtime_wait":true}
```

While idle, the Engine does not call the model or advance the step. A runtime
event, cancellation, or runtime deadline wakes it. Events are drained only before
the next model request and are appended as runtime-sourced user context. QitOS
does not forge a second tool result for a tool call that has already ended.

Unmarked `Decision.wait()` retains its existing immediate-loop behavior for parser
repair and search backtracking.

## Protocol resolution

`Engine` resolves the model protocol while capturing each immutable turn, using the
following precedence:

1. The `protocol` passed directly to `Engine`.
2. `agent.model_protocol`.
3. A protocol inferred from the Engine or Agent parser.
4. `agent.llm.qitos_protocol`, then `agent.llm.qitos_harness_metadata["protocol"]`.
5. A protocol inferred from the model name.
6. The framework default, `react_text_v1`.

The model-level declarations in step 4 are attached by `build_model_for_preset(...)`. This means direct construction such as `Engine(agent=agent)` preserves an explicitly selected family preset even when the provider model name is an alias that QitOS cannot infer. Unknown model-level protocol identifiers are ignored so the existing model-name and framework fallbacks remain available. Traces record `model_qitos_protocol` or `model_harness_metadata` as the resolution source when either declaration is selected.

The selected protocol stays fixed for that turn. Configuration or model changes made
while it runs are resolved only when the next turn snapshot is captured.

## Empty model responses

After a model call, the Engine records the normalized response. When the selected model
policy prefers native tool calls and the provider returns `tool_calls`, those calls are
authoritative: the Engine bypasses `AgentModule.interpret_model_response()` and the text
parser, then commits one terminal tool result per call id in the provider's original
order. A mixed batch of executable and policy-blocked calls follows the same single
commit path, so a blocked result cannot be duplicated or moved ahead of an earlier call.
If a native call has a missing name or malformed arguments, QitOS does not reinterpret
the assistant text as a separate action. It preserves the call id, skips execution, and
returns a recoverable protocol error in the corresponding tool-result turn.

For API or hybrid tool-schema delivery in this native mode, QitOS also omits its
framework-owned text action contract from the system prompt. Agent-authored task and
final-result instructions remain unchanged. If API delivery is unavailable and prompt
injection becomes the effective fallback, the text contract remains available.

For responses outside that native-call branch, the Engine gives
`AgentModule.interpret_model_response()` the first opportunity to turn the response into
a decision. If the hook returns `None` and the response contains neither non-whitespace
text nor tool calls, the Engine classifies the result as a `model_error` before it reaches
the parser. The default recovery path retries once; a second consecutive empty response
stops the run with `unrecoverable_error` instead of consuming the remaining step budget
as parser `wait` decisions.

The `model_output` event and `StepRecord.model_response` still retain the response's `finish_reason`, usage, model, and provider fields. This guard does not change native tool-call responses, explicit `Decision.wait` values, or parser feedback for non-empty malformed model output.

## `Engine.run(task)`

```python
result = engine.run(task)
```

Accepts a plain string objective or a structured `Task` object. Returns an `EngineResult`.

When you pass a `Task`, the Engine extracts the budget from `task.budget` and overrides the Engine's own budget for that run. It also orchestrates resource staging and environment lifecycle (reset, observe, close) automatically.

## `EngineResult`

```python
@dataclass
class EngineResult(Generic[StateT]):
    state: StateT
    records: List[StepRecord]
    events: List[RuntimeEvent]
    step_count: int
    task_result: Optional[TaskResult]
```

| Field          | Description                                                               |
| -------------- | ------------------------------------------------------------------------- |
| `state`        | Final typed state after the run. Check `state.final_result` and `state.stop_reason`. |
| `records`      | One `StepRecord` per step, containing decision, observation, and diffs.   |
| `events`       | All `RuntimeEvent` objects emitted during the run.                        |
| `step_count`   | Number of steps executed (`len(records)`).                                |
| `task_result`  | Structured outcome including success flag and criterion results.           |

Typical usage:

```python
result = engine.run("summarize the paper")

print(result.state.final_result)   # the agent's final answer
print(result.state.stop_reason)    # why the loop ended
print(result.step_count)           # how many steps ran
print(result.task_result.success)  # whether success criteria passed
```

## Hooks

Hooks observe and react to lifecycle events without modifying Engine internals. They implement `EngineHook` and are called at `on_before_step` and `on_after_step` boundaries.

```python
engine.register_hook(my_hook)
engine.unregister_hook(my_hook)
engine.clear_hooks()
```

You can also pass hooks at construction time via the `hooks` parameter, or at run time via `agent.run(hooks=[...])`.

## Budget exhaustion

When a step, wall-clock, token, or cost budget is exhausted, Engine sets a distinct
`state.stop_reason` and emits an `END` event. Tool concurrency and Child count are
admission bounds rather than completion reasons. The run terminates gracefully and
still returns `EngineResult`.

```python
import time

from qitos.engine.states import RuntimeBudget

engine = Engine(
    agent=agent,
    budget=RuntimeBudget(
        max_steps=30,
        max_runtime_seconds=120.0,
        max_tokens=50_000,
        max_cost_usd=2.0,
        max_tool_concurrency=4,
        max_children=4,
        # Optional outer scheduler deadline; the earlier limit wins.
        deadline_monotonic=time.monotonic() + 120.0,
    ),
)
```

Cost limits never guess from model names. Pass `model_pricing=ModelPricing(...)` to
Engine, or expose a typed `pricing` value on the configured Model.

The effective run deadline is shared by Engine step admission, runtime waits, tool
admission and timeout, and tool retry backoff. Expiry requests graceful termination; it
does not claim that Python forcibly killed a synchronous call already in progress.

## Building an Engine from AgentModule

`AgentModule.build_engine()` is a convenience factory that creates an Engine pre-bound to the agent:

```python
engine = agent.build_engine(
    budget=RuntimeBudget(max_steps=15),
    trace_writer=trace_writer,
)
result = engine.run(task)
```

This is equivalent to `Engine(agent=agent, ...)` and is what `agent.run()` calls internally.

## Async execution

`Engine` has one async-native execution path. `arun()` runs on the caller's event loop,
and model providers stream without a worker-thread bridge.

```python
from qitos import Engine

engine = Engine(agent=agent, budget=RuntimeBudget(max_steps=20))
result = await engine.arun("analyze the data")
print(result.state.final_result)
```

Call synchronous `engine.run()` only at a synchronous application boundary. It raises
`RuntimeError` inside an active event loop so the application cannot accidentally nest
event loops.

### `Engine.arun_stream(task)`

Run the agent loop and yield structured `EngineEvent` objects as they occur — ideal for real-time UI updates or streaming progress to a client.

```python
async for event in engine.arun_stream("analyze the data"):
    print(event.event_type, event.step_id, event.payload)
```

Events are emitted at step boundaries (`step_start`, `step_end`), phase transitions (`decide`, `act`, `reduce`, `critic`, `check_stop`), and multi-agent events (`handoff`, `delegate`, `fanout`). The stream includes one `run_start` and ends with exactly one `run_end`. Event queues are bounded: intermediate deliveries may be dropped under sustained backpressure, `dropped_event_count` records that loss, and the `run_end` payload includes the count while retaining terminal priority.

### `EngineEvent`

```python
@dataclass
class EngineEvent:
    event_type: EngineEventType   # step_start, step_end, decide, act, ...
    step_id: int
    agent_id: str | None          # which agent produced this step
    phase: RuntimePhase | None
    ok: bool
    payload: Dict[str, Any]
    error: str | None
    ts: str                       # ISO 8601 timestamp
```

### `EventStream`

`EventStream` is the async queue that underpins `arun_stream()`. You can also use it standalone to fan out events to multiple consumers:

```python
from qitos.engine.events import EventStream

stream = EventStream()
q1 = stream.subscribe()  # asyncio.Queue for consumer 1
q2 = stream.subscribe()  # asyncio.Queue for consumer 2
```

### Model streams

All model providers implement the canonical async `Model.stream(request)` contract.
The Engine assembles one immutable `ModelRequest` after History projection and passes
that exact value to the Provider. Its message and option projections are isolated from
mutation, while its absolute deadline is shared by connection, stream, retry, and
cleanup work. A Journal-backed run stores the credential-redacted request snapshot in
`model.completed` before any tool can start.

OpenAI Responses may return a Run-bound continuation handle. The next request sends
`previous_response_id` and only the incremental input when the Provider, model,
protocol, non-input settings, and full canonical prefix all still match. A resumed Run
can reuse that handle. A fork has a different Run id, and Provider/model changes,
compaction changes, or an invalid/expired handle send the complete local transcript.
History remains the recovery source; continuation is never required to resume.

Anthropic Messages persists its message id, thinking signature, native content blocks,
and usage in the canonical response/history representation. It does not advertise a
server-side continuation handle because Messages replay is transcript-based.

Each Provider yields discriminated `ModelStreamEvent` values. Text, reasoning,
ToolCall deltas, native output items, usage, and lifecycle notifications have distinct
event kinds, so a consumer never infers semantics from a combination of optional
fields. Every transaction ends with exactly one `COMPLETED` or `FAILED` event. Only a
`COMPLETED` event can contribute finish state, final ToolCalls, or a continuation;
`FAILED` is an error terminal and is never committed as a model response.

Class tools implement `async execute(...)`. A legacy synchronous decorated function is
run in the isolated compatibility boundary and cancellation waits for that call to reach
a known side-effect boundary. Native subprocess, managed Web, MCP, Mailbox, and Child
implementations are asynchronous and do not create temporary event loops.

```python
from qitos.models import OpenAICompatibleModel

llm = OpenAICompatibleModel(
    model="qwen-plus",
    api_key="...",
    base_url="https://...",
)
engine = Engine(agent=MyAgent(llm=llm))
result = await engine.arun("analyze the data")
```
