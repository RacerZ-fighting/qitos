---
title: "Trace artifacts"
description: "Inspect QitOS trace directories with the read-only qita tools."
---

QitOS runs write one trace directory per Run when a trace producer is attached:

```text
<trace_logdir>/<run_id>/
  manifest.json
  events.jsonl
  steps.jsonl
```

`qitos.trace.AgentTraceProducer` reattaches this format to the `Agent` façade event
stream. Each committed turn publishes its events (model, tool and turn phases)
together with one `TraceStep` (step id = turn) as one transaction; lifecycle events
write directly; the manifest finalizes with the terminal status (`completed`,
`failed`, `stopped`) and a summary qita can read. Payloads carry Tool call ids,
names and statuses — never credentials; the writer applies the established trace
redaction. The `SessionHarness` attaches a producer to every journal run when it is
constructed with `trace_directory=...`.

While a Run is active, qita derives its displayed event count, step count, and latest
update time from the committed JSONL files. Once the producer finalizes the Run, the
validated manifest summary becomes authoritative.

<Note>
Trace artifacts are an observational projection. Nothing in Session recovery reads
them, and they cannot create an executable resume or fork — the canonical Session
Journal is the only recovery truth.
</Note>

## What each file means

| File | Purpose |
| --- | --- |
| `manifest.json` | Run summary and producer-supplied reproducibility metadata |
| `events.jsonl` | Event stream recorded by the trace producer |
| `steps.jsonl` | Committed turn markers with event index ranges |

For one trace directory, these files are the evidence that `qita` displays. They do
not replace the canonical Session Journal and cannot create an executable resume or
fork.

Older artifacts may contain fields such as `prompt_protocol`, `parser_name`,
`run_spec`, `experiment_spec`, or benchmark metadata. Those fields describe the
producer that wrote that artifact. They do not enable a parser, Decision/Action
lifecycle, benchmark runner, or Engine in the current Agent path.

## Inspect trace artifacts

```bash
qita board --logdir ./runs
qita replay --run ./runs/<run_id>
qita export --run ./runs/<run_id> --html ./report.html
```

Use these commands to review, compare, and export existing evidence. Remote models and
external environments remain nondeterministic, so artifact replay is an inspection
operation rather than deterministic re-execution.

To continue a Run from a safe boundary, resume or fork its canonical Session Journal
through `qitos.kit.session.SessionHarness`. Copying or editing a trace directory
never creates a resumable Run.
