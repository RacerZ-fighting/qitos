---
title: Session journal
description: Persist complete model and tool transactions for resume and fork.
---

QitOS persists one append-only JSONL journal per Run. When configured, the journal
is the canonical record of model transactions, Tool transactions, turn commits, and
run lifecycle for the minimal agent loop.

Each journal instance is one storage owner. `create()` or `open()` acquires an
operating-system writer lease for that Run. A competing process receives
`JournalOwnershipError` instead of opening a second writer. A closed instance
rejects mutations permanently, but its isolated replay and committed-tool query
view remain available for diagnostics.

## Loop transaction order

The loop's `JournalTurnTransaction` records each turn in this order:

1. `model.completed` — one finalized model transaction, success or failure
2. `tool.started` — a durable execution permit for one admitted ToolCall
3. execute the handler
4. finalize the canonical `ToolResult`
5. `tool.terminal`
6. `step.committed` — the turn's committed messages plus the
   `terminal_record_ids` linking its Tool terminals

`tool.started` is a durable execution permit. If it cannot be written, the handler is
not invoked. The finalized terminal result is persisted once and is the same deeply
immutable value delivered to the transcript. Parallel Tool batches commit results in
input order, and every admitted call receives exactly one terminal result, including
denied, timed-out, and cancelled calls.

A run ends in exactly one terminal record: `run.completed` carries the terminal
status (`completed`, `failed`, `max_turns`, `deadline_exceeded`) and the run's new
messages; an aborted run appends `run.interrupted` instead. External task
cancellation and faults terminalize started work and the run record before
re-raising, so a run never ends without a terminal record.

## Durability and projections

The JSONL writer waits for durable acknowledgement for every record. Darwin uses
`F_FULLFSYNC`. Other POSIX systems prefer `fdatasync` when available.

Every append first converts its payload into one isolated strict JSON value. Python
tuples become JSON arrays; non-string object keys, non-finite numbers, bytes, sets,
cycles, and custom objects are rejected before any record is written. The same value
therefore drives in-memory replay, stable-record-id settlement, JSONL encoding, and
reopened replay.

`journal.index.sqlite3` is a disposable read projection beside the canonical file.
QitOS updates it only after the JSONL append is durable. A missing, stale, corrupt, or
unsupported projection is rebuilt from validated JSONL records. Open and replay always
parse canonical JSONL first; SQLite never supplies replay records. Complete JSONL
records with invalid semantics raise `JournalCorruptionError`. Valid records using an
unsupported old or new schema raise `JournalUnsupportedVersionError`. Both fail
closed; only an unterminated syntactically torn tail is truncated during recovery.

`JsonlRunCatalog` is the read-only side of this boundary. It can inspect or list Runs
while their writer lease remains active, and it can validate ancestor and direct-child
lineage without constructing an Agent. A catalog read uses the current complete JSONL
prefix; SQLite remains a disposable index and never supplies canonical records.
`RunStatus.RESUMABLE` means only that no durable `run.completed` exists.

Each `RunHandle` also exposes a stable `lineage_id`, the immediate `parent_run_id`,
the latest durable `committed_position`, a `continuation_position`, and
`has_terminal_state`.

```python
from qitos.kit.journal import JsonlRunCatalog, JsonlSessionJournal

catalog = JsonlRunCatalog(".qitos/sessions")
handle = await catalog.inspect_run(run_id)
all_runs = await catalog.list_runs()
ancestors = await catalog.lineage(run_id)

if handle.is_terminal and handle.continuation_position is not None:
    source = JsonlSessionJournal(".qitos/sessions")
    await source.open(handle.run_id)
    child = await source.fork(handle.continuation_position, "follow-up-run")
    await child.close()
    await source.close()
```

Forking accepts only a committed `JournalPosition`. The child journal owns an
independent inherited prefix and can resume without its ancestors. An inherited local
commit is itself a valid boundary, so forked Runs may be forked again. Every returned
open journal remains owned by its caller until `close()` is called.

## Committed tool lookup

Every canonical Tool terminal is discoverable through a lightweight
`JournalRecordRef` locator once its terminal record is durable:

```python
from qitos.core.journal import JournalRecordRef

reference = JournalRecordRef(run_id=origin_run_id, record_id=terminal_record_id)
transaction = journal.find_tool_transaction(reference)
if transaction is not None:
    result = transaction.result
```

The lookup is read-only and returns a fresh typed `ToolTransaction` only after the
terminal is named by a `step.committed` record. Opening a journal rebuilds this query
view from its canonical JSONL records. A fork resolves inherited terminals by the
parent's origin reference, so the child does not copy the result into a second store.
Unknown, uncommitted, or child-renamed references return `None`. Only the loop's
record schema is decodable; records written by the retired Engine taxonomy fail
closed.

## Child and mailbox records

Child supervision writes `child.started` before constructing the child Agent and
`child.terminal` before parent notification. Recovery rebuilds a started child from
its own loop journal when that journal holds a durable run terminal record, and
closes it as `interrupted` otherwise; it never reattaches or replays a child Agent.
A terminal created during recovery is persisted before the supervisor reports
recovered results. Forks preserve inherited facts for audit but receive no control
authority over parent handles.

Parent messages to an active child are journaled as `runtime_input.posted` before
the message enters the child run's steering queue, so mailbox acceptance is
journal-recoverable and the message becomes visible at the child's next turn safe
point.
